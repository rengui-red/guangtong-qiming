\## 五、文档维护规则



\### 5.1 文档的生命周期



| 层 | 更新频率 | 维护人 |

|----|----------|--------|

| 00\_root | 永不更改 | 创始人 |

| 01\_charter | 极少更改 | 核心团队 |

| 02\_footprints | 持续更新 | 记录者 |

| 03\_stories | 持续增补 | 内容团队 |

| 04\_resources | 每月更新 | 运营团队 |

| 05\_character\_database | 持续构建 | 数据团队 |

| 06\_xihe\_ai | 迭代更新 | 技术团队 |

| 07\_engineering | 跟随迭代 | 技术团队 |



\### 5.2 文档的修改流程



1\. 提 Issue 说明修改原因

2\. Fork 仓库

3\. 修改文档

4\. 提 Pull Request

5\. 核心团队审核

6\. 合并



\### 5.3 文档的格式规范



\- 全部使用 Markdown

\- 标题层级：`#` → `##` → `###`

\- 表格对齐

\- 代码块标注语言

\- 链接使用相对路径

\## 六、文件命名规范



\### 6.1 中文文件名



\- 用于给人看的文档

\- 示例：`前后端联调手册.md`



\### 6.2 英文文件名



\- 用于给机器读的文档

\- 示例：`tone\_config.json`



\### 6.3 混合命名



\- 结构文件用英文

\- 内容文件用中文
